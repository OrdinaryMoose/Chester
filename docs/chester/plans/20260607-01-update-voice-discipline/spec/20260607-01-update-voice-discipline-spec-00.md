# Spec: Canonical instruction-injection — build-time agent generator

**Sprint:** 20260607-01-update-voice-discipline
**Parent brief:** docs/chester/working/20260607-01-update-voice-discipline/design/20260607-01-update-voice-discipline-design-01.md
**Architecture:** Hybrid — one unified generator, full-file generation of agent `.md` files from canonical sources via a per-concern manifest; catalog as a mode of the same tool; CLAUDE.md two-tier and the two orphan voice rules handled as plain authoring edits.

## Goal

Eliminate cross-file duplication of shared instruction text in Chester by making each shared rule set live in exactly one canonical source and materializing the agent `.md` files that consume it through a deterministic build-time generator. A verify test guards staleness so a canonical edit that is not regenerated fails CI/test — converting silent inline drift into a mechanical, `git diff`-detectable signal. The generator + its verify test land together; neither lands alone.

## Components

**Generator (new)**
- `bin/chester-generate-agents` — thin PATH wrapper, mirrors `bin/chester-config-read`/`bin/chester-trailer-write`; `exec`s the implementation.
- `chester-util-config/chester-generate-agents.sh` — implementation. Reads `agents/manifest.json`, emits every declared output whole. Flags: `--output-dir DIR` (write outputs under DIR instead of repo paths, preserving relative paths — used by the verify test); default invocation generates agent files AND catalog. `jq` guard mirroring `chester-config-read.sh`; clear non-zero error if `jq` absent.
- Determinism: fixed fragment order from the manifest array; alphabetical sort for the catalog list; NO timestamps or variable content injected into generated bodies. Same inputs → identical bytes.
- Each generated agent file opens with a fixed header comment: `<!-- generated by bin/chester-generate-agents — edit canonical sources under agents/sources/ (and skills/util-design-partner-role/SKILL.md), not this file -->`.

**Manifest (new)**
- `agents/manifest.json` — two keys: `agents` (array) and `catalog` (object).
- Each `agents` entry: `output` (repo-relative path), `frontmatter` (literal YAML: name/description/tools/model), `fragments` (ordered array; each fragment is either a whole source file path or a `{file, section}` pair naming a `##` heading to extract from that file).
- `catalog` entry: `output` = `skills/setup-start/references/skill-index.md`; `scan_glob` = `skills/*/SKILL.md`; `template` = the hand-authored catalog template path with a slot marker.

**Canonical sources (new / extended — single source of truth)**
- `skills/util-design-partner-role/SKILL.md` — ALREADY canonical for Stance Principles (`## Stance Principles (carry into every turn)`, `:162`). The generator extracts that section as a fragment for member agents (no third copy). NOTE: this file explicitly DEFERS the Translation Gate ("Translation Gate (defined in design skills)" at `:33` and `:120`) — it is NOT canonical for the Gate. The shared member-facing Translation-Gate band therefore has its canonical home in `agents/sources/member-scaffold.md`, reproducing the members' current one-line restatement. ADD two new sections here: `## PM Litmus Test` and `## Research Boundary` (no canonical home today); these are read at runtime by parent-session design skills and are NOT baked into agent files.
- `agents/sources/review-discipline.md` (new) — canonical evidence standard, ≥80 confidence ladder, independence rule. One canonical phrasing settles the per-reviewer wording-variant question at authoring time.
- `agents/sources/member-scaffold.md` (new) — the shared member bands: phase-contract shared text, Hard Prohibitions, Output-Format preamble, peer-DM caveman-ultra rule, C1/C2 meta, and the member-facing Translation-Gate band (canonical here, since `util-design-partner-role` defers the Gate).
- `agents/sources/lens-{conservator,innovator,pragmatist,purist}.md` (new) — per-lens content: Lens Position, persona elaboration, lens-specific C1/C2 example, and any lens-specific framing of the shared principles. All lens-varying prose lives here, hand-authored.
- `agents/sources/reviewer-{attacker,smeller,reviewer,spec-reviewer,quality-reviewer}.md` (new) — each reviewer's domain-specific body (what it reviews); the shared discipline arrives via the `review-discipline.md` fragment.
- `agents/sources/catalog-template.md` (new) — the hand-authored skill-index header, priority order, dispatch patterns, and role grouping, with a single `<!-- CATALOG_SLOT -->` marker where the generated skill list is inserted.

**Generated outputs (regenerated, committed, loaded directly at dispatch)**
- `agents/design-committee-{conservator,innovator,pragmatist,purist}.md` (4 member agents).
- `agents/{plan-build-plan-attacker,plan-build-plan-smeller,plan-build-plan-reviewer,execute-write-spec-reviewer,execute-write-quality-reviewer}.md` (5 reviewer agents).
- `skills/setup-start/references/skill-index.md` (catalog).

**Verify test (new — the mandatory regeneration trigger)**
- `tests/test-generated-agents-current.sh` — regenerate to a temp dir (`--output-dir`), whole-file `diff` each manifest output against the committed file, fail on any mismatch with `FAIL: <path> stale — run bin/chester-generate-agents`. PLUS a manifest-completeness check: glob `agents/*.md` EXCLUDING `agents/CLAUDE.md` (documentation, not an agent), and assert every remaining file is either a manifest output (the 9 generated) or on the declared hand-authored exclusion list: `design-committee-consolidator`, `design-committee-scribe`, `design-committee-researcher` — distinct roles, not advocacy lenses. (`team-lead` is NOT an agent file — it lives at `skills/design-committee/references/team-lead.md` — so it is outside this partition.) Follows `tests/` conventions: `set -euo pipefail`, `mktemp -d`+trap, `fail()` accumulator, `PASS/FAIL` footer.

**Authoring edits (NOT generator inputs)**
- Root `CLAUDE.md` — canonical for the version-bump rule (reinstate the dropped "not on typo fixes or comment-only edits" carve-out) and the description-sync rule; fix the description-sync target to name `skills/setup-start/references/skill-index.md`.
- `skills/CLAUDE.md` — replace the duplicated rule bodies with two-tier pointers up to root `CLAUDE.md`; carry no rule body root already owns.

## Data Flow

- **Authoring:** developer edits a canonical source (e.g. `agents/sources/member-scaffold.md` or a `## Stance Principles` section in `util-design-partner-role/SKILL.md`) → runs `bin/chester-generate-agents` → generated `agents/*.md` + `skill-index.md` rewritten whole → commit both source and generated output.
- **Generation:** manifest drives iteration. Per agent entry: emit header comment + frontmatter + each fragment in order (whole-file or extracted `##` section). Per catalog: scan `skills/*/SKILL.md` frontmatter, render the list, splice into the template slot.
- **Verification:** `tests/test-generated-agents-current.sh` regenerates to temp and diffs against committed; mismatch = stale = fail.
- **Dispatch (unchanged):** the plugin loads `agents/*.md` directly as subagent prompts; runtime-varying content (dispatch question, context packets) continues to arrive via `SendMessage`/`TeamCreate` payload (dispatch-time injection, already in place — out of scope to change).

## Error Handling

- **Missing `jq`** → generator exits non-zero with a one-line message; verify test reports the dependency failure, does not silently pass.
- **Malformed manifest / missing fragment file / missing named section** → generator exits non-zero naming the offending entry; no partial write to committed paths (write to temp, move on success).
- **Fragment section not found** (a `{file, section}` whose `##` heading is absent) → hard error, not an empty splice.
- **New agent file with no manifest entry and not in the exclusion list** → verify test fails (manifest-completeness check), preventing a silently un-generated agent.
- **Stale output** (canonical edited, not regenerated) → verify test fails with the regenerate instruction.

## Testing Strategy

- **Verify/staleness test** (`tests/test-generated-agents-current.sh`) — the primary new test; whole-file diff + manifest-completeness. This IS the regeneration trigger.
- **Determinism check** — generating twice yields identical bytes (can be a sub-assertion of the verify test or a sibling).
- **Voice-rule canonical-home assertions** — extend `tests/test-partner-role-discipline.sh` to assert `## PM Litmus Test` and `## Research Boundary` sections exist in `util-design-partner-role/SKILL.md`.
- **CLAUDE.md dedup assertions** — `grep` checks: `skills/CLAUDE.md` carries no version-rule body; root `CLAUDE.md` carries the restored carve-out; neither names the phantom `setup-start/SKILL.md` list.
- **Semantic-equivalence gate (one-time, authoring)** — first generation must reproduce the current agents' meaning: the shared bands move to canonical sources seeded from existing text so the first regenerate produces no meaning change; committee contracts (Final Position schema, routing signal, consolidator read-scope) survive in the generated member/role files.
- Run via existing harness: `bash tests/test-<name>.sh`.

## Constraints

- Generated agent files MUST stay tracked — dispatch loads them directly; no runtime build step _(structural)_.
- Generator MUST be deterministic (same inputs → same bytes) or the diff test is unstable _(structural)_.
- `bin/` wrapper + `chester-util-config/*.sh` implementation split MUST be followed _(normative — repo convention)_.
- Tests MUST be self-contained bash, clean up after themselves, assume hostile CWD, print a grep-able `PASS/FAIL` footer _(normative — `tests/CLAUDE.md`)_.
- Consolidator, scribe, researcher are distinct roles — NOT generated from the member scaffold; they stay hand-authored and on the exclusion list. `agents/CLAUDE.md` is documentation excluded from the completeness glob. `team-lead` is not an `agents/` file at all _(structural — committee redesign 20260606-01)_.
- Stance Principles has exactly one canonical home (`util-design-partner-role/SKILL.md:162`); the generator extracts, never copies, it — no third copy. The member Translation-Gate band's canonical home is `agents/sources/member-scaffold.md` (that file defers the Gate); it is authored once there, not extracted from `util-design-partner-role` _(structural)_.
- Editing a generated `agents/*.md` by hand is no longer the authoring path; the header comment states this _(normative)_.
- Skill `description` frontmatter remains the single source for catalog descriptions; the index is derived _(structural — FD-03)_.

## Non-Goals

- FD-05 (review-loop control flow) — out of scope.
- Round/turn flow structures — distinct by design, not duplicated; untouched.
- Dispatch-time injection mechanism and runtime-read parent-session skills — already correct; not changed.
- A pre-commit hook or CI wiring — optional hardening; the floor is the generator + the bash verify test. (May be noted as follow-on.)
- Changing the *meaning* of any agent's instructions — this sprint relocates and single-sources text; it does not rewrite disciplines (except settling the reviewer evidence-phrasing variant at authoring time).
