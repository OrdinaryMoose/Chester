INNOVATOR R1 DM — PROCESS CROSS-POLE CRITIQUE

CONSERVATOR: Right — Clerk-certified session close ("not a designer declaration") is load-bearing; designer reads the gate result, does not compute it. Wrong: collapsing axiom-assertion into OPEN means OPEN spans two distinct states — no axioms yet vs axioms being asserted. These have different valid operations; treating them as one state allows deliberation to open before any axiomatic anchor exists, which is the Elicitron failure mode Alternative F was specifically designed to close. Push: one-hop bounded cascade means a Proposition grounded on a Proposition grounded on a revised entry escapes the cascade entirely — Purist's transitive-until-no-new-rows is a stronger guarantee for the same Clerk work. Why stop at one hop?

PRAGMATIST: Right — cascade synchronous with triggering event, not deferred to round close, is correct; deferring cascade to round close allows a pole to submit new Propositions in the same round grounded on a now-invalid entry before Clerk flags it. Wrong: three phases with no CLERK-AUDIT state means there is no named machine-checkable point where Clerk work is complete and ratification is permitted to open — the transition into ratification is ambiguous as to whether Clerk has finished. Push: round ends when "Clerk completes lint pass and presents ratification surface" — but who triggers the lint pass? If team-lead, that is an actor decision belonging in macro step 4; if automatic on pole submission count, that is Purist's auto-close which Pragmatist does not explicitly adopt.

PURIST: Right — full-batch reject with Clerk flagging specific failures is the cleanest structural move; per-row accept in a mixed batch creates partial-ratification state that Clerk must track separately from full-batch state, adding schema complexity for a case that is rare in practice. Wrong: automatic round-close trigger (condition b: all Concerns COVERED and no REVISED-PENDING) fires during DELIBERATING before designer has seen the round — closing a round without designer signal violates two-player asymmetric authority; the designer must be the one to advance, not the system. Push: CLOSING as a fifth transitional state between RATIFYING and CLOSED — what work happens in CLOSING that cannot happen in RATIFYING? If it is only gate-check computation, that is Clerk work within RATIFYING, not a separate phase.
