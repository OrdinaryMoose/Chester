Deepening candidates

1 · Collapse the four advocacy-member files onto the protocol seam

Strong

Files

  • agents/design-committee-conservator.md (106 L)
  • agents/design-committee-innovator.md (106 L)
  • agents/design-committee-pragmatist.md (105 L)
  • agents/design-committee-purist.md (105 L)
  • + researcher.md (123 L) — partial overlap
  • → references/member-protocol.md (the seam)

Problem

Each advocacy file is ~70–75% word-for-word identical to the other three. The shared mass: Scope, Hard Prohibitions, Voice Discipline, and the Output Format templates. Only Lens Position and the persona/phase-contract gloss are genuinely lens-specific. A change to a prohibition or a voice rule is a four-file (five with researcher) hand-edit with no enforcement that they stay in sync.

skill-contract.md:23 — the charter the files have already drifted from

"Agent files carry lens, voice, phase contract only. No sprint refs, no schemas, no product names, no gating conditions."

Yet conservator.md:43–49 (Hard Prohibitions), :51–62 (full Voice Discipline), :64–105 (full Output Format) are reproduced identically in all four. The charter says "voice" belongs here — but identical voice in four files is duplication, and a citation satisfies "carry voice" without the copy.

Solution

Move the shared blocks into member-protocol.md — already the single authority every advocacy file cites, already loaded on demand via the member's Read tool. Add three citable ## sections there (Hard Prohibitions, Voice Discipline, Output Format), the same way ## Final Position already lives there as sole authority. Each agent file shrinks to its lens: Lens Position, the persona gloss, the phase-contract gloss, and a one-line "shared protocol per member-protocol.md §…" pointer. No @include needed — these files load as system prompts, so the mechanism is citation, exactly as committee-root resolution already works.

Benefits — locality & leverage

  • Locality: a prohibition or voice-rule change concentrates in one file instead of fanning across five.
  • Leverage: member-protocol.md already carries the routing-signal and Final-Position authority; this raises its behaviour-per-line without widening its interface.
  • The interface becomes the test surface: "is a new member lens correct?" reduces to reading one short lens file, not diffing 106 lines against three siblings.
  • Charter realignment: brings the agent files back to skill-contract.md:23's stated intent — lens-only, schema-free.

Deletion test. Delete the shared blocks from three of the four files: the complexity does not vanish — it reappears the moment any of the four must be reconstructed or kept consistent. That "reappears across N callers" is the signal the prose was earning its keep and belongs behind one seam.

2 · One canonical per-round sequence, not two numbered copies

Worth exploring

Files

  • team-lead.md:93–106 — Conversation Loop Per-Round Flow (11 steps)

Problem

The same round is numbered twice with incompatible boundaries. SKILL.md's step 4 (Consolidate) is split into team-lead's steps 4–5; SKILL.md folds members-write + members-signal into one region, team-lead splits them and inserts a ledger step. 3 · Stop re-deriving the C1/C2 voice rules in seven files

Worth exploring

Files

Authority: util-design-partner-role/SKILL.md. Restated in: SKILL.md:58–68, team-lead.md:28–40 & :288–296, and the Voice Discipline block of conservator / innovator / pragmatist / purist / researcher (lines ~51–62 each).

Problem

The Translation Gate, Option-naming, C1 (Externalized Coverage) and C2 (Fact Default) rules are named as load-bearing and cited correctly — then spelled out again, in full, in seven downstream files. The single authority exists; the copies undercut it. Any change to the voice contract is a seven-file audit.

Note — overlaps candidate 1

Five of the seven restatements live in the member/researcher agent files. If candidate 1 lands, the member-side Voice Discipline collapses into member-protocol.md automatically — and member-protocol can itself carry a single citation to util-design-partner-role rather than reproducing C1/C2. That leaves only team-lead.md's two restatements to reduce to pointers.

Caveat: a deliberate amount of redundancy here is defensible — voice is the floor and a member dispatched cold benefits from seeing it inline. The recommendation is to reduce the full restatement to a tight cited summary, not to delete the reminder.

Solution

Designate util-design-partner-role the sole prose owner of C1/C2/Translation-Gate. Downstream files keep a one-line named pointer plus only the lens-specific deviation (e.g. purist's "say kind, not tagged-union"). The enforcement checklist (team-lead's self-eval) stays — it references rules by name, it does not re-teach them.

Benefits

  • Locality: the voice contract has one home; a change there propagates by reference.
  • Leverage: the LOAD-BEARING citation stops competing with seven near-copies that can silently diverge from it.
  • Reader bounce on "what are the voice rules?" drops from 5+ files to one.

4 · Fold the researcher into the same member base

Speculative

Files

agents/design-committee-researcher.md (123 L)

Problem

The researcher shares the same Scope / Voice Discipline / write-then-send / Final-Position boilerplate as the four advocacy files, but is not an advocacy lens — it holds no design opinion. It rides along in the duplication set without being part of the four-lens grid.

Why speculative

The researcher's Final Position is a degenerate case (position = "no design opinion") and its prohibitions differ (no advocacy, owns absence findings). Folding it into the shared base is correct for the mechanics sections but risks blurring the no-opinion boundary if done carelessly. Worth doing only as a follow-on to candidate 1, with the opinion-boundary kept explicit in the researcher's thin file.

Benefits

  • One shared mechanics seam for all five dispatched roles instead of two near-identical copies (advocacy base + researcher).
  • Keeps the researcher file focused on what is actually unique: its research scope and the no-opinion contract.

Also noted — handled well, leave alone

Committee-root resolution

Single authority in member-protocol.md:149–161; cited (not restated) from SKILL.md, team-lead.md, round-format. This is the pattern candidates 1–3 should imitate.

Final Position schema

Sole authority in member-protocol.md:71–114; downstream files cite by heading. Correct.

Consolidator depth

consolidator.md is a genuinely deep module — a hard enumerate-only ceiling behind a tiny interface. No change.

Top recommendation

Tackle candidate 1 first — collapse the advocacy files onto the protocol seam.

It is the highest-leverage move and the lowest-risk: the seam already exists, the files already cite it, and the target file is already the established authority for member mechanics. It is the only candidate backed cleanly by the deletion test — ~70–75% of four (soon five) files is duplicated prose whose complexity reappears across every caller. It also subsumes most of candidate 3: folding the members' Voice Discipline into member-protocol removes five of the seven voice restatements for free. Land it, then candidate 2 (one numbered round sequence) as an independent cleanup, with candidates 3–4 as follow-ons.

One guard worth honouring during the work: skill-contract.md:23 forbids sprint-specific overlay on agent files. This refactor moves shared invariant prose to a shared file — it does not add anything sprint-specific anywhere — so it is consistent with the contract, and in fact restores the agent files to the "lens, voice, phase-contract only" shape the contract already prescribes.
