# Alignment Map — Round 02

## Refined question
Given the observed problem that design-specify's front half (competing-architecture review, prior-art, architecture selection) redundantly re-derives architecture the comprehensive committee already settled — wasting significant tokens just to reach the hardening passes — how should the committee/spec path expand to eliminate that waste?

## Answer shape
**Converged spine (4-0) with one narrow preserved sub-split (3-1).** The core mechanism is settled; only the bridge artifact is contested. A must-resolve contract-definition requirement rides on top.

## Converged finding (4-0) — CF3
**design-specify gains a conditional entry path ("Path B") that consumes already-settled committee architecture and skips its front half**, proceeding directly to spec authorship + the unchanged three-pass hardening chain. The front half is load-bearing only when architecture is unsettled; it is pure redundant spend when a committee verdict has already terminated with settled architecture.
- Warrant (logic + in-scope designer-premise, verified): designer R02 reframe (granted as fact); design-specify SKILL.md — the front half's stated purpose is to settle what the brief left open, so it is conditionally redundant; Purist supplies the load step ("same output category — settled architecture").
- **CF1 preserved.** This does NOT make the committee author specs. The fix lives in design-specify skipping its own already-done work — the symmetric move that does not trigger Round 01's category-collapse objection. All four affirm CF1 still holds.
- Pragmatist locates the cost precisely: design-specify's three-parallel-dispatch architecture step is the dominant token cost; skipping it eliminates the re-derivation "at near-zero incremental cost."

## Preserved sub-split (3-1) — what bridges committee output into Path B

### Option B1 (no new committee artifact) — Conservator, Pragmatist, Purist defend.
design-specify reads the committee's EXISTING output to trigger the skip. Three flavors of the same shape: a conditional branch keyed on architecture-selection presence (Conservator); a wrapping skill emitting an architecture-settled flag + architecture summary (Pragmatist); design-specify's verdict-as-input entry contract (Purist). The committee emits nothing new; its verdict already IS the settled architecture.
- Advantage: zero change to committee internals/contract; minimum surface; both categories untouched.
- Disadvantage: design-specify must parse/validate a free-form verdict against the entry contract — the qualifying-input definition carries the risk.
- Warrant (logic, verified): Purist — "eliminating redundancy requires only that design-specify acquire a conditional entry path, not that the committee change what it produces"; Pragmatist minimal-coupling reasoning; Conservator localization.

### Option B2 (committee emits a typed spec-precursor) — Innovator defends.
The scribe emits an architecture-settled spec-precursor alongside the verdict — a structured re-format of existing committee artifacts (verdict, alignment-map, researcher-findings) shaped as clean design-specify input. design-specify forks on precursor-present.
- Advantage: design-specify consumes a typed, purpose-built input rather than parsing a free-form verdict; scribe already reads all the source data, so it's reformatting, not new derivation.
- Disadvantage: scribe output bifurcation (new template section); requires the team-lead to declare architecture-focus in the convening message so non-architecture consults don't emit a precursor.
- Warrant (in-scope designer-premise, verified): Innovator — "scribe already reads all the source data; producing a second structured output is a reformatting, not new work."

## Must-resolve contract requirement (raised by 2, uncontested)
Whichever bridge is chosen, **design-specify's Path B entry contract must define what a committee verdict must contain to qualify as architecture-settled input** — Purist names F-A-C-equivalent evidence (feasibility / suitability / completeness). Under-specify it and Path B admits unverified verdicts, building a spec on an unverified architecture foundation. Conservator's blocking risk echoes this: prior failures (StoryDesigner rev-a) came from an undefined stage boundary. This is authoring risk, resolved by precise contract definition — not a reason to reject Path B.
